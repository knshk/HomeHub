P — Proposed

A launcher, then one thing at a time

The core move: stop treating eleven destinations as one flat row. Land on a home screen that shows the whole product, and open a single feature when it's chosen. Chat then gets the full screen it needs — and adding features later grows a grid instead of squeezing a rail.

Build list

What each change actually costs

Roughly ordered cheapest-first, so you can green-light any subset.

P6

Strip the topbar

Drop "Home Hub / on your WiFi" at phone width (keep the house mark), swap the user-badge text for a round avatar, and move Log out into Settings — it's used once a year and costs a permanent button today.

Cost: a few lines of CSS plus one markup tweak. Frees ~54px on every screen.

P7

Shrink the model picker to a chip

Replace the Model label + <select> with a chip in the chat header showing the current model; tap opens a sheet listing local and cloud models, keeping the "leaves your home" warning where the choice is actually made.

Cost: small — the model list already loads; it just renders in a sheet instead of a select.

P8

Put chat history behind the count chip

Hide .chat-sidebar below 820px and surface it as a bottom sheet from the header chip. Desktop keeps the sidebar, where there's room for it.

Cost: small — same markup, shown in a sheet. This alone fixes the odd landing.

P9

Move install into the launcher grid

Retire the fixed pill; render the offer as a dashed tile (and keep the Settings entry we already added for the Android certificate route).

Cost: small, and it removes an element that overlaps content.

P10

Add the launcher and make it the landing

A new home view: greeting, status line, grouped tiles with live counts. Tabs stay as the desktop navigation; on phones the launcher replaces them, and each feature gets a back arrow. Chat stops being the default destination.

Cost: the real piece of work — one new view, a router tweak, and per-tile count queries. Everything above stands on its own if you'd rather stage it.

P11

Open question: launcher or bottom bar?

A launcher suits a many-featured appliance and scales cleanly. A bottom tab bar (Chat · Calendar · Home · More) is faster for the four things used daily, and sits in thumb reach. They can coexist — launcher as home, bottom bar inside features.

Needs your call before I build P10 — it changes the navigation model.
